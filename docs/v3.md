# Chore Fridge v3

v3 is a fridge experience station. Chores stay, but they are one module among others.

v2 remains the running household board. This branch is where v3 work lands.

## Direction

- A household has **family members**. Members can be **children** or **adults**. The old “kid” label is gone.
- An **account picker** chooses whose station you are looking at. The all-in-one household board stays as a layout option.
- The UI is **cards**. Built-in cards cover chores, rewards, and balances. Custom cards can be added without rewriting the shell.
- Themes **stack**. A base look, a holiday overlay, and a member overlay can apply together. Themes use WordPress-style **actions and filters** so a card or theme can hook display, data, and chrome without a private paint bus.
- The server **pushes** state. Clients subscribe. The five-second refresh timer is not the source of truth. v2 already pings revision over SSE and then pulls the board; v3 should send the subscribed payload, not only a revision number.
- A **native mobile app** ships as a first-class client of the same household server. NativeScript is acceptable. Sharing the domain and API matters more than sharing every pixel.

## Server

- Subscriptions per household, per member, and per card when a card has its own document.
- Commands stay the write path. Subscribers see the result after commit.
- Keep the append-only ledger and daily board as the accounting core.
- Preserve the household document shape at the persistence boundary unless a v3 migration is explicit.

## Cards

- The shell is a card host: account bar, theme stack, card grid or stack.
- A card declares id, title, where it can run (fridge, member, adult, child), and which stores it reads.
- Custom cards are modules the household can enable. They must not introduce an app-wide render cycle. Construct their DOM once and update nodes they own, same as JSOX today.

## Themes

- Multiple theme layers can be on at once (for example Classic + Holidays + a member accent).
- Hooks: `doAction(name, payload)` and `applyFilters(name, value, payload)` for chrome, copy, and class lists.
- Holiday and season extras from v2 become a stackable theme, not a single exclusive look.

## Accounts

- Member records replace `kids`. Existing kids migrate to members with role `child`.
- Adults can complete chores, redeem, and use parent tools according to permissions.
- Compact-style “one person fills the screen” becomes the default member station. Household overview remains available.

## Native app

- Same server, same commands, same subscriptions.
- Phone and tablet layouts use the member station first.
- Evaluate NativeScript (native UI) against a WebView wrapper that reuses the JSOX shell. Choose once a thin account-picker prototype exists.

## Fridge station

Cards that belong here later, after the shell is real:

- Chores and rewards (from v2)
- Calendar / skipped-day catch-up
- Notes and lists
- Photos
- Weather
- Timers and kitchen helpers

## Carried from v2

These v2 roadmap items move here:

- Member-specific theme for only their card
- Shared tasks (finisher gets credit, done for everyone)
- Time-travel browsing UI
- Login to mark tasks done, and real authentication
- Custom themes without editing source
- Mobile app
- Custom background separate from theme

## First slices

1. Branch shell: this document, member rename plan, no behavior change yet.
2. Server subscriptions that push board (or member) documents on commit.
3. Account picker + member station, household overview still available.
4. Card host with chores as the first card.
5. Stackable themes with holiday as a layer.
6. Native app prototype against the same API.
